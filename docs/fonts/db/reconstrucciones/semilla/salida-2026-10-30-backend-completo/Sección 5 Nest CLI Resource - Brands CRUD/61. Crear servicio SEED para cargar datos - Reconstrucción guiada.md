## Objetivo de la lección

Crear un recurso seed con un único GET /seed que delega en SeedService.populateDB, para que cualquier desarrollador pueda recargar datos de prueba con una sola petición.

## Estado inicial heredado

Proyecto car-dealership con CarsModule (carros en un arreglo privado) y BrandsModule creado con el CLI en las lecciones 59–60; aún sin base de datos ni variables de entorno.

## Fase 1 — Generar el recurso seed

**Objetivo:** Generar el recurso seed.

**Código o cambio acumulativo:**

```bash
nest g res seed --no-spec
```


**Por qué:** El CLI crea módulo, controlador y servicio y registra SeedModule en AppModule; el instructor prefiere generar y borrar lo sobrante.

**Cómo comprobarlo y resultado esperado:** Aparece src/seed y AppModule importa SeedModule.

**Procedencia:** E3.

## Fase 2 — Recortar el controlador a un GET

**Objetivo:** Recortar el controlador a un GET.

**Código o cambio acumulativo:**

```ts
import { Controller, Get } from '@nestjs/common';
import { SeedService } from './seed.service';

@Controller('seed')
export class SeedController {
  constructor(private readonly seedService: SeedService) {}

  @Get()
  runSeed() {
    return this.seedService.populateDB();
  }
}
```


**Por qué:** La semilla no recibe datos del cliente; un GET basta para dispararla.

**Cómo comprobarlo y resultado esperado:** GET http://localhost:3000/seed responde.

**Procedencia:** E4.

## Fase 3 — Dejar en el servicio un único método

**Objetivo:** Dejar en el servicio un único método.

**Código o cambio acumulativo:**

```ts
import { Injectable } from '@nestjs/common';

@Injectable()
export class SeedService {
  populateDB() {
    return 'SEED Executed';
  }

```


**Por qué:** La lógica vive en el servicio; por ahora solo confirma que se ejecuta.

**Cómo comprobarlo y resultado esperado:** La respuesta es SEED Executed.

**Procedencia:** E5 / E6.
