## Objetivo de la lección

Definir los datos de semilla como constantes TypeScript tipadas y preparar en CarsService y BrandsService un método que los reciba.

## Estado inicial heredado

SeedModule con GET /seed que devuelve 'SEED Executed' (lección 61). Cars y Brands guardan sus datos en arreglos privados.

## Fase 1 — Semilla de carros tipada

**Objetivo:** Semilla de carros tipada.

**Código o cambio acumulativo:**

```ts
import { v4 as uuid } from 'uuid';
import { Car } from '../../cars/interfaces/car.interface';

export const CARS_SEED: Car[] = [
  {
    id: uuid(),
    brand: 'Toyota',
    model: 'Corolla',
  },
  {
    id: uuid(),
    brand: 'Honda',
    model: 'Civic',
  },
  {
    id: uuid(),
    brand: 'Jeep',
    model: 'Cherokee',
  },
];
```


**Por qué:** Tipar la semilla con la interfaz del dominio detecta datos mal formados al compilar.

**Cómo comprobarlo y resultado esperado:** Importar CARS_SEED en SeedService compila.

**Procedencia:** E1 / E2 / E3 / E4 / E5.

**Por qué:** La entidad Brand es una clase sin dependencias inyectadas, así que se puede importar directamente.

**Cómo comprobarlo y resultado esperado:** Importar BRANDS_SEED compila.

**Procedencia:** E6 / E7.

## Fase 3 — Métodos de carga en los servicios

**Objetivo:** Métodos de carga en los servicios.

**Código o cambio acumulativo:**

```ts
// Miembro añadido al final de CarsService
fillCarsWithSeedData(cars: Car[]) {
  this.cars = cars;
}


// Miembro añadido al final de BrandsService
fillBrandsWithSeedData(brands: Brand[]) {
  this.brands = brands;
}
```


**Por qué:** Los arreglos son privados; el único acceso desde fuera es un método público del servicio.

**Cómo comprobarlo y resultado esperado:** Ambos servicios compilan con el nuevo método.

**Procedencia:** E8 / E9 / E10.
