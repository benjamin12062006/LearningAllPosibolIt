## Objetivo de la lección

Guardar las contraseñas de los usuarios sembrados con el mismo hash bcrypt que AuthService, para que el login funcione con ellos.

## Estado inicial heredado

La semilla inserta usuarios con contraseña en texto plano (lección 186); AuthService.create usa bcrypt.hashSync(password, 10) (lección 168).

## Fase 1 — Hashear en los datos de la semilla

**Objetivo:** Hashear en los datos de la semilla.

**Código o cambio acumulativo:**

```ts
import * as bcrypt from 'bcrypt';

interface SeedUser {
  email: string;
  fullName: string;
  password: string;
  roles: string[];
}

export const initialData: SeedData = {
  users: [
    {
      email: 'test1@google.com',
      fullName: 'Test One',
      password: bcrypt.hashSync('Abc123', 10),
      roles: ['admin'],
    },
    {
      email: 'test2@google.com',
      fullName: 'Test Two',
      password: bcrypt.hashSync('Abc123', 10),
      roles: ['user', 'super'],
    },
  ],
  products: [
    // ...productos del adjunto (lección 148)
  ],
};
```


**Por qué:** Los usuarios sembrados deben ser indistinguibles de los registrados por la API.

**Cómo comprobarlo y resultado esperado:** Tras la semilla, POST de login con test1@google.com y Abc123 devuelve el token; otra contraseña falla.

**Procedencia:** E7 / E8 / E1 / E2 / E3 / E4 / E5 / E6.
