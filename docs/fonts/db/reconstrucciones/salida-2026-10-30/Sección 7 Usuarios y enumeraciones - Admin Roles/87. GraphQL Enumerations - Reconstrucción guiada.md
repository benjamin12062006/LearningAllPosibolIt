## Objetivo de la lección

Usar una enumeración TypeScript (ValidRoles) como tipo de argumento GraphQL registrándola con registerEnumType, para que el esquema valide y sugiera los valores.

## Estado inicial heredado

UsersResolver.findAll recibe ValidRolesArgs (lección 86) con roles tipado como string[]; el enum ValidRoles existe en auth/enums.

## Fase 1 — Tipar el argumento con el enum

**Objetivo:** Tipar el argumento con el enum.

**Código o cambio acumulativo:**

```ts
@Field(() => [ValidRoles])
roles: ValidRoles[] = [];
```


**Por qué:** Se quiere que el esquema ofrezca solo roles válidos en vez de cualquier string.

**Cómo comprobarlo y resultado esperado:** Al guardar aparece el error "cannot determine a GraphQL input type".

**Procedencia:** E1 / E2.

## Fase 2 — Registrar el enum

**Objetivo:** Registrar el enum.

**Código o cambio acumulativo:**

```ts
import { registerEnumType } from '@nestjs/graphql';

export enum ValidRoles {
  admin = 'admin',
  user = 'user',
  superUser = 'superUser',
}

registerEnumType(ValidRoles, {
  name: 'ValidRoles',
  description: 'Lorem ipsum: roles permitidos',
});
```


**Por qué:** A diferencia de clases (decoradores), los enums se registran una vez con nombre y descripción.

**Cómo comprobarlo y resultado esperado:** Apollo Studio sugiere admin, superUser y user; un valor como user2 se rechaza sin ejecutar el resolver.

**Procedencia:** E3 / E4 / E5 / E6.

## Fase 3 — Consultar con roles

**Objetivo:** Consultar con roles.

**Código o cambio acumulativo:**

```graphql
{
  users(roles: [superUser]) {
    fullName
    email
    roles
  }
}
```


**Por qué:** El filtro real con QueryBuilder llega en la lección 88.

**Cómo comprobarlo y resultado esperado:** La consulta valida; el resultado aún no filtra.

**Procedencia:** E7.
