## Objetivo de la lección

Proteger un Query con un guard JWT adaptado a GraphQL: extender AuthGuard("jwt") de Passport y sobrescribir getRequest con GqlExecutionContext.

## Estado inicial heredado

AuthModule con signup/login que devuelven AuthResponse (token y usuario), PassportModule, JwtModule y JwtStrategy (lecciones 72–74).

## Fase 1 — Declarar el Query protegido

**Objetivo:** Declarar el Query protegido.

**Código o cambio acumulativo:**

```ts
@Query(() => AuthResponse, { name: 'revalidate' })
revalidateToken(/* @CurrentUser() user: User */): AuthResponse {
  throw new Error('No implementado');
}
```


**Por qué:** Es un Query porque no recibe datos del cliente; sirve para comprobar el flujo antes de implementarlo.

**Cómo comprobarlo y resultado esperado:** revalidate responde el error "No implementado".

**Procedencia:** E1 / E2 / E3.

## Fase 2 — Comprobar que AuthGuard de Passport no basta

**Objetivo:** Comprobar que AuthGuard de Passport no basta.

**Código o cambio acumulativo:**

```ts
@UseGuards(AuthGuard())
```


**Por qué:** En GraphQL la request no está donde Passport la busca; el error es confuso (no puede leer propiedades de undefined).

**Cómo comprobarlo y resultado esperado:** La consulta falla con el error de propiedades indefinidas; se retira este decorador.

**Procedencia:** E4 / E5.

## Fase 3 — Crear JwtAuthGuard

**Objetivo:** Crear JwtAuthGuard.

**Código o cambio acumulativo:**

```ts
import { ExecutionContext } from '@nestjs/common';
import { GqlExecutionContext } from '@nestjs/graphql';
import { AuthGuard } from '@nestjs/passport';

export class JwtAuthGuard extends AuthGuard('jwt') {
  // ! Override
  getRequest(context: ExecutionContext) {
    const ctx = GqlExecutionContext.create(context);
    const request = ctx.getContext().req;
    return request;
  }
}
```


**Por qué:** Se reutiliza la estrategia jwt de Passport y solo se cambia cómo obtener la request: desde el contexto GraphQL.

**Cómo comprobarlo y resultado esperado:** Con @UseGuards(JwtAuthGuard), sin token responde 401.

**Procedencia:** E6 / E7 / E8 / E9.

## Fase 4 — Enviar el token

**Objetivo:** Enviar el token.

**Código o cambio acumulativo:**

```text
Authorization: Bearer <token devuelto por login>
```


**Por qué:** Los headers compartidos de Apollo Studio evitan repetirlo en cada operación.

**Cómo comprobarlo y resultado esperado:** Con token, la estrategia recibe el payload (id, iat, exp) y se llega a "No implementado".

**Procedencia:** E10.

# Experimentos temporales y límites

@UseGuards(AuthGuard()) se prueba y se elimina. La estrategia imprime el payload y devuelve error a propósito hasta la lección 76.
