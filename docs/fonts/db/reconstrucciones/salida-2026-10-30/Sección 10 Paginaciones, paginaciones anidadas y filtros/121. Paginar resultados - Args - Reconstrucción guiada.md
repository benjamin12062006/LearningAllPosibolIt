## Objetivo de la lección

Crear un ArgsType reutilizable PaginationArgs (offset y limit opcionales con valores por defecto y validación) en un módulo common, y recibirlo en el Query items.

**Procedencia:** E3 / E4.

## Fase 2 — Definir PaginationArgs

**Objetivo:** Definir PaginationArgs.

**Código o cambio acumulativo:**

```ts
import { ArgsType, Field, Int } from '@nestjs/graphql';
import { IsOptional, Min } from 'class-validator';

@ArgsType()
export class PaginationArgs {
  @Field(() => Int, { nullable: true })
  @IsOptional()
  @Min(0)
  offset: number = 0;

  @Field(() => Int, { nullable: true })
  @IsOptional()
  @Min(1)
  limit: number = 10;
}
```


**Por qué:** ArgsType agrupa argumentos de Query; Int evita decimales; nullable + valores por defecto lo hacen opcional; class-validator impone mínimos.

**Cómo comprobarlo y resultado esperado:** El esquema documenta offset: Int = 0 y limit: Int = 10.

**Procedencia:** E5 / E6 / E7 / E8 / E9 / E10.

## Fase 3 — Recibirlo en items

**Objetivo:** Recibirlo en items.

**Código o cambio acumulativo:**

```ts
@Query(() => [Item], { name: 'items' })
async findAll(
  @CurrentUser() user: User,
  @Args() paginationArgs: PaginationArgs,
): Promise<Item[]> {
  console.log({ paginationArgs });
  return this.itemsService.findAll(user);
}
```


**Por qué:** Con @Args() sin nombre, las propiedades del ArgsType se exponen como argumentos sueltos.

**Cómo comprobarlo y resultado esperado:** items sin argumentos imprime { offset: 0, limit: 10 }; items(limit: 0) da Bad Request.

**Procedencia:** E10 / E11 / E12.
