## Objetivo de la lección

Aplicar limit y offset en ItemsService.findAll con take y skip de TypeORM, conservando el filtro por usuario.

## Estado inicial heredado

ItemsResolver recibe PaginationArgs pero no lo usa (lección 121).

## Fase 1 — Pasar los args al servicio

**Objetivo:** Pasar los args al servicio.

**Código o cambio acumulativo:**

```ts
@Query(() => [Item], { name: 'items' })
async findAll(
  @CurrentUser() user: User,
  @Args() paginationArgs: PaginationArgs,
): Promise<Item[]> {
  return this.itemsService.findAll(user, paginationArgs);
}
```


**Por qué:** El resolver solo traduce; el servicio aplica la paginación.

**Cómo comprobarlo y resultado esperado:** Compila.

**Procedencia:** E1.

## Fase 2 — Aplicar take y skip

**Objetivo:** Aplicar take y skip.

**Código o cambio acumulativo:**

```ts
async findAll(user: User, paginationArgs: PaginationArgs): Promise<Item[]> {
  const { limit, offset } = paginationArgs;
  // TODO: filtrar

  return this.itemsRepository.find({
    take: limit,
    skip: offset,
    where: {
      user: {
        id: user.id,
      },
    },
  });
}
```


**Por qué:** take limita el número de filas y skip salta las primeras; el filtro por usuario se mantiene.

**Cómo comprobarlo y resultado esperado:** items(limit: 2) devuelve dos; offset 2, 4… avanza por páginas.

**Procedencia:** E2 / E3 / E4.

# Resumen mental

PaginationArgs → servicio → take/skip. Los campos anidados (users { items }) no heredan la paginación: hay que declararla en su propio resolver de campo.
