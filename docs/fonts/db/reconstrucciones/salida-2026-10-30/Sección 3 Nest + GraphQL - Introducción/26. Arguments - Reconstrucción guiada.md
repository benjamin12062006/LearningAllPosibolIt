## Objetivo de la lección

Recibir argumentos en un Query con @Args, fijar su tipo GraphQL (Int), hacerlo opcional con nullable y un valor por defecto, y pedir varios campos con alias en una sola petición.

## Estado inicial heredado

HelloWorldResolver con hello (String), randomNumber (Float, Math.random()*100) y randomFromZeroTo (Int, Math.floor(Math.random()*10)) de las lecciones 24 y 25.

## Fase 1 — Recibir el argumento to

**Objetivo:** Recibir el argumento to.

**Código o cambio acumulativo:**

```ts
@Query(() => Int, { name: 'randomFromZeroTo' })
getRandomFromZeroTo(@Args('to') to: number): number {
  return Math.floor(Math.random() * to);
}
```


**Por qué:** GraphQL no adivina nada: el argumento se declara con @Args y su nombre es el que se expone al cliente.

**Cómo comprobarlo y resultado esperado:** La consulta exige to; randomFromZeroTo(to: 5) devuelve 0–4.

**Procedencia:** E3 / E4.

## Fase 2 — Forzar el tipo Int y documentar

**Objetivo:** Forzar el tipo Int y documentar.

**Código o cambio acumulativo:**

```ts
@Query(() => Int, { name: 'randomFromZeroTo', description: 'From zero to argument TO (default 6)' })
getRandomFromZeroTo(@Args('to', { type: () => Int }) to: number): number {
```


**Por qué:** TypeScript solo tiene number; sin type GraphQL infiere Float y aceptaría 5.333.

**Cómo comprobarlo y resultado esperado:** El esquema muestra to: Int! y 5.333 produce error de validación.

**Procedencia:** E5 / E6.

## Fase 3 — Hacerlo opcional con valor por defecto

**Objetivo:** Hacerlo opcional con valor por defecto.

**Código o cambio acumulativo:**

```ts
@Args('to', { nullable: true, type: () => Int }) to: number = 6,
```


**Por qué:** El valor por defecto de TypeScript no basta si el esquema sigue marcándolo obligatorio (!); nullable lo libera.

**Cómo comprobarlo y resultado esperado:** randomFromZeroTo sin argumento responde un entero entre 0 y 5.

**Procedencia:** E7 / E8.

## Fase 4 — Varios campos con alias en una petición

**Objetivo:** Varios campos con alias en una petición.

**Código o cambio acumulativo:**

```graphql
{
  dadoDe10: randomFromZeroTo(to: 10)
  dadoDe20: randomFromZeroTo(to: 20)
  dadoDe5: randomFromZeroTo(to: 5)
}
```


**Por qué:** Los alias permiten repetir el mismo campo con argumentos distintos; todo viaja en una sola petición HTTP.

**Cómo comprobarlo y resultado esperado:** La respuesta incluye las tres claves con sus números.

**Procedencia:** E9.

## src/hello-world/hello-world.resolver.ts

Procedencia: E1, E2, E3 (estado previo); E4–E8.

```ts
import { Args, Float, Int, Query, Resolver } from '@nestjs/graphql';

@Resolver()
export class HelloWorldResolver {
  @Query(() => String, { description: 'Hola Mundo es lo que retorna', name: 'hello' })
  helloWorld(): string {
    return 'Hola Mundo';
  }

  @Query(() => Float, { name: 'randomNumber' })
  getRandomNumber(): number {
    return Math.random() * 100;
  }

  @Query(() => Int, { name: 'randomFromZeroTo', description: 'From zero to argument TO (default 6)' })
  getRandomFromZeroTo(
    @Args('to', { nullable: true, type: () => Int }) to: number = 6,
  ): number {
    return Math.floor(Math.random() * to);
  }
}
```

# Resumen mental

@Args(nombre, { type, nullable }) define el contrato del argumento en el esquema; el tipo TypeScript y el default solo actúan dentro del método.
