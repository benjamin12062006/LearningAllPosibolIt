## Objetivo de la lección

## Fase 1 — Conservar el contrato de fuentes

**Objetivo:** Conservar el contrato de fuentes.

**Código o cambio acumulativo:**

```ts
type FileSource = { type: 'file'; path: string };
type DBSource = { type: 'db'; connectionUrl: string };
type Source = FileSource | DBSource;
```


**Por qué:** El guard recibe una unión conocida, cuyos miembros tienen formas distintas. No recibe unknown.

**Cómo comprobarlo y resultado esperado:** Observar type file/db y la propiedad específica de cada alternativa.

**Procedencia:** E4 / E5.

## Fase 2 — Extraer la decisión con un nombre

**Objetivo:** Extraer la decisión con un nombre.

**Código o cambio acumulativo:**

```ts
function isFile(source: Source) {
```

**Por qué:** La condición sigue siendo la misma; isFile expresa su significado al lector y TypeScript infiere el predicado.

**Cómo comprobarlo y resultado esperado:** El editor debe inferir source is FileSource en el retorno de isFile.

## Fase 3 — Leer el flujo desde loadData

**Objetivo:** Leer el flujo desde loadData.

**Código o cambio acumulativo:**

```ts
function loadData(source: Source) {
  if (isFile(source)) {
    // Aquí se abriría el archivo con source.path.
```

**Por qué:** La función usa la decisión nombrada, retorna tras el caso de archivo y deja la alternativa de base al final.

**Cómo comprobarlo y resultado esperado:** Dentro del if puede accederse a source.path; después del return, a source.connectionUrl. Son comprobaciones previstas, no ejecución del curso.

**Procedencia:** E3 / E4 / E5.

## guards.ts

Procedencia: E1–E5. Esqueleto didáctico ensamblado: no se inventan valores de ejemplo, importaciones ni operaciones de IO ausentes.

```ts
type FileSource = { type: 'file'; path: string };
type DBSource = { type: 'db'; connectionUrl: string };
type Source = FileSource | DBSource;

function isFile(source: Source) {
  return source.type === 'file';
}

function loadData(source: Source) {
  if (isFile(source)) {
    // Aquí se abriría el archivo con source.path.
    return;
  }
  // Aquí se conectaría la base con source.connectionUrl.
}
```

# Resumen mental

Un guard nombrado transmite intención al lector y estrechamiento a TypeScript. La función principal conserva el flujo visible; separar la condición no elimina las comprobaciones necesarias.
