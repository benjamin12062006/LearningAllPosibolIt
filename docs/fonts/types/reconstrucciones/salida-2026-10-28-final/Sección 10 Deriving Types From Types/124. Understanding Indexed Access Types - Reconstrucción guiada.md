## Estado inicial heredado

Se conocen typeof y keyof; esta lección define AppUser manualmente y extrae parte de su tipo.

## Fase 1 — Tipo de usuario

**Objetivo:** Tipo de usuario.

**Código o cambio acumulativo:**

```ts
type AppUser = {
  name: string;
  age: number;
  permissions: { id: string; title: string; description: string }[];
};
```


**Por qué:** Un único tipo contiene la estructura de los permisos.

**Cómo comprobarlo y resultado esperado:** Revisar que permissions es un array de objetos con tres campos string.

**Procedencia:** E1.

## Fase 2 — Extraer parte del tipo

**Objetivo:** Extraer parte del tipo.

**Código o cambio acumulativo:**

```ts
type Perms = AppUser['permissions'];
```


**Por qué:** El acceso se realiza sobre un tipo y mantiene su relación con el origen.

**Cómo comprobarlo y resultado esperado:** Un cambio en permissions se refleja en Perms sin copiar la definición.

**Procedencia:** E2 / E3.

## indexed-access.ts

Procedencia: E1, E2, E3. AppUser, Perms y las propiedades name, age, permissions, id, title y description constan en la explicación. La sintaxis se ensambla y indexed-access.ts es una ruta documental: el original no fija nombre de archivo. No se inventan valores del appUser alternativo, pues la transcripción no los da.

```ts
type AppUser = {
  name: string;
  age: number;
  permissions: {
    id: string;
    title: string;

  }[];

type Perms = AppUser['permissions'];
```
