## Objetivo de la lección

Obtener el usuario autenticado en una ruta con un decorador de parámetro propio (GetUser) en lugar de leer la request completa, y lanzar un 500 si el guard no lo dejó en la request.

## Estado inicial heredado

AuthController con la ruta GET /api/auth/private protegida por @UseGuards(AuthGuard()), que devuelve ok y un mensaje (lección 175). La estrategia JWT deja el usuario en request.user.

## Fase 1 — Ver dónde está el usuario

**Objetivo:** Ver dónde está el usuario.

**Código o cambio acumulativo:**

```ts
@Get('private')
@UseGuards(AuthGuard())
testingPrivateRoute(
  @Req() request: Express.Request,
) {
  console.log({ user: request.user });

  return {
    ok: true,
    message: 'Hola Mundo Private',
  };
}
```


**Por qué:** Antes de abstraer, se comprueba qué deja el guard en la request.

**Cómo comprobarlo y resultado esperado:** La consola muestra request.user con los datos del usuario.

**Procedencia:** E2 / E3.

## Fase 2 — Crear el decorador de parámetro

**Objetivo:** Crear el decorador de parámetro.

**Código o cambio acumulativo:**

```ts
export const GetUser = createParamDecorator(
  (data, ctx: ExecutionContext) => {
    console.log({ data });
    return 'Hola Mundo';
  },
);
```


**Por qué:** Muestra que lo que devuelve el callback es lo que llega al parámetro y qué contiene data.

**Cómo comprobarlo y resultado esperado:** La respuesta muestra 'Hola Mundo'; con @GetUser('email') la consola muestra data = 'email'.

**Procedencia:** E1 / E5 / E6 / E7 / E8 / E9 / E10 / E11.

## Fase 3 — Devolver el usuario o lanzar un 500

**Objetivo:** Devolver el usuario o lanzar un 500.

**Código o cambio acumulativo:**

```ts
import {
  createParamDecorator,
  ExecutionContext,
  InternalServerErrorException,
} from '@nestjs/common';

export const GetUser = createParamDecorator(
  (data, ctx: ExecutionContext) => {
    const req = ctx.switchToHttp().getRequest();
    const user = req.user;

    if (!user)
      throw new InternalServerErrorException('User not found (request)');

    return user;
  },
);

@Get('private')
@UseGuards(AuthGuard())
testingPrivateRoute(
  @GetUser() user: User,
) {
  return {
    ok: true,
    message: 'Hola Mundo Private',
    user,
  };
}
```


**Por qué:** Usar el decorador fuera de una ruta con guard es un error de programación del backend, no del cliente.

**Cómo comprobarlo y resultado esperado:** Con token válido la respuesta incluye al usuario; con otro usuario cambia la información.

**Procedencia:** E4 / E12 / E13 / E14 / E15.
