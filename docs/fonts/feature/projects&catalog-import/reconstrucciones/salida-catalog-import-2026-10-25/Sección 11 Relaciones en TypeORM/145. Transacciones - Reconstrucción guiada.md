## Objetivo de la lección

Actualizar producto e imágenes con un QueryRunner de TypeORM: iniciar transacción, realizar escrituras mediante el mismo manager, confirmar o revertir y liberar el recurso.

## Fase 1 — Preparar el producto y empezar la transacción

**Objetivo:** Preparar el producto y empezar la transacción.

**Código o cambio acumulativo:**

```ts
const { images, ...toUpdate } = updateProductDto;
const product = await this.productRepository.preload({ id, ...toUpdate });
if (!product) throw new NotFoundException(`Product with id ${id} not found`);

const queryRunner = this.dataSource.createQueryRunner();
await queryRunner.connect();
await queryRunner.startTransaction();
```


**Por qué:** La preparación verifica el recurso. A partir de startTransaction, las escrituras que deben ser atómicas se ejecutan con el manager del mismo runner. No basta con crear el runner y seguir usando escrituras ajenas a él.

**Cómo comprobarlo y resultado esperado:** En la aplicación original, comprobar que un ID inexistente se rechaza y que se espera la conexión antes de ejecutar las escrituras. Esta guía no ejecuta esa aplicación.

**Procedencia:** E1 / E8 / E9.

**Objetivo:** Cerrar éxito y fallo sin confundir SQL con lectura posterior.

**Código o cambio acumulativo:**

  await queryRunner.rollbackTransaction();

**Por qué:** Commit confirma las escrituras; rollback revierte si fallan. El runner se libera en los dos caminos descritos por el instructor. findOnePlain vuelve a consultar después de confirmar y liberar; esa lectura no forma parte de la transacción terminada.

**Cómo comprobarlo y resultado esperado:** En el ejercicio completo, un fallo durante escritura debe conservar el estado anterior; el camino nominal debe devolver el producto consultado. ## src/products/products.service.ts — método update recuperado; clase heredada incompleta

Procedencia: E8/E9: preparación heredada de 144; E1: inicio; E2/E3/E4/E10: escrituras; E5/E6: cierre en éxito/error; E7: lectura final. Se muestra todo el método recuperable, no una clase inventada. NotFoundException/mensajes, nombres e imports no disponibles se declaran en el estado inicial; deben cotejarse con el material original.

```ts
// Miembro de ProductsService; no es un archivo autónomo.
// La clase/imports/métodos heredados no se recuperan íntegros en estas fuentes.
async update(id: string, updateProductDto: UpdateProductDto) {
  const { images, ...toUpdate } = updateProductDto;
  const product = await this.productRepository.preload({ id, ...toUpdate });
  if (!product) {
    throw new NotFoundException(`Product with id ${id} not found`);
  }

  const queryRunner = this.dataSource.createQueryRunner();
  await queryRunner.connect();
  await queryRunner.startTransaction();

  try {
    if (images) {
      await queryRunner.manager.delete(ProductImage, { product: { id } });
      product.images = images.map((image) =>
        this.productImageRepository.create({ url: image }),
      );
    }
    await queryRunner.manager.save(product);
    await queryRunner.commitTransaction();
    await queryRunner.release();
    return this.findOnePlain(id);
  } catch (error) {
    await queryRunner.rollbackTransaction();
    await queryRunner.release();
    this.handleDBExceptions(error);
  }
}
```
