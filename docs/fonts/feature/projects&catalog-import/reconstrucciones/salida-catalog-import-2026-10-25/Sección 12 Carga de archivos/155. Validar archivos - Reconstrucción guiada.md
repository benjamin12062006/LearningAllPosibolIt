## Objetivo de la lección

Añadir un fileFilter del módulo Files al FileInterceptor del endpoint de imágenes y convertir el archivo ausente o rechazado en BadRequestException en el controlador.

## Estado inicial heredado

La lección 154 genera FilesModule/FilesController/FilesService y crea POST /files/product, con UploadedFile y FileInterceptor('file'). Ese ejemplo recibe una imagen pero todavía no escribe en disco ni registra metadatos en base. La clase 155 modifica el controlador y añade un helper; FilesModule y FilesService generados no cambian y su contenido no se inventa.

## Fase 1 — Conectar el punto de extensión del interceptor

**Objetivo:** Conectar el punto de extensión del interceptor.

**Código o cambio acumulativo:**

```ts
export const fileFilter = (
  req: Express.Request,
  file: Express.Multer.File,
  callback: Function,
) => {
  return callback(null, true);
};

// En FilesController:
@UseInterceptors(FileInterceptor('file', { fileFilter }))
```


**Por qué:** Primero se observa que el interceptor invoca el helper. Se entrega la referencia fileFilter; llamarlo al configurar el decorador no tendría la request ni el archivo de esa carga.

**Cómo comprobarlo y resultado esperado:** En el proyecto original, enviar multipart con campo file debe pasar por el helper. Este true inicial acepta todo: es un estado temporal, no el filtro final.

**Procedencia:** E1 / E2 / E8 / E9.

## Fase 2 — Aceptar únicamente las extensiones de imagen mencionadas

**Objetivo:** Aceptar únicamente las extensiones de imagen mencionadas.

**Código o cambio acumulativo:**

```ts
if (!file) return callback(new Error('File is empty'), false);
const fileExtension = file.mimetype.split('/')[1];
const validExtensions = ['jpg', 'png', 'gif'];
if (validExtensions.includes(fileExtension)) return callback(null, true);
callback(null, false);
```


**Por qué:** El callback decide si ese archivo pasa al controlador. La lista reconstruida conserva solo los valores inequívocos de la narración; el dato se obtiene del MIME declarado, por lo que esta técnica no valida bytes de imagen ni equivale a un parser CSV.

**Cómo comprobarlo y resultado esperado:** Con MIME declarado image/png el helper acepta; con application/pdf rechaza. Verificar el comportamiento en el curso, sin concluir que una etiqueta MIME demuestra contenido auténtico.

**Procedencia:** E3 / E4 / E5 / E6.

## Fase 3 — Distinguir rechazo del archivo y respuesta HTTP

**Objetivo:** Distinguir rechazo del archivo y respuesta HTTP.

**Código o cambio acumulativo:**

```ts
if (!file) {
  throw new BadRequestException('Make sure that the file is an image');
}
return { fileName: file.originalname };
```


**Por qué:** El filtro puede dejar file indefinido sin lanzar un error HTTP. El controlador del ejemplo exige un archivo y por eso convierte ese caso en Bad Request antes de leer originalname.

**Cómo comprobarlo y resultado esperado:** En el proyecto del curso, ausencia o PDF rechazado debe llegar al 400 y una imagen aceptada debe devolver su nombre. No se ejecutó esta comprobación al generar la guía.

**Procedencia:** E6 / E7 / E10.

## src/files/helpers/fileFilter.helper.ts

Procedencia: E1/E2: función helper y firma; E3: rama sin archivo; E4/E5: MIME/lista y aceptación; E6: rechazo sin excepción HTTP. Function es la forma descrita por el instructor; mensajes y grafías se normalizan con las incertidumbres iniciales.

```ts
export const fileFilter = (
  req: Express.Request,
  file: Express.Multer.File,
  callback: Function,
) => {
  if (!file) return callback(new Error('File is empty'), false);

  const fileExtension = file.mimetype.split('/')[1];
  // Valores inequívocos del audio; cotejar lista exacta con el material original.
  const validExtensions = ['jpg', 'png', 'gif'];

  if (validExtensions.includes(fileExtension)) return callback(null, true);
  callback(null, false);
};
```

## src/files/files.controller.ts

Procedencia: E8/E9 y lección 154: decoradores, campo file y endpoint product; E1: helper; E6/E7/E10: rechazo y respuesta. Constructor del recurso Files generado en la lección 154 se conserva como contexto de scaffold, sin afirmar una implementación de FilesService. Imports y mensajes reconstruidos; no hay almacenamiento en disco en este estado.

```ts
import { BadRequestException, Controller, Post, UploadedFile, UseInterceptors } from '@nestjs/common';
import { FileInterceptor } from '@nestjs/platform-express';
import { FilesService } from './files.service';
import { fileFilter } from './helpers/fileFilter.helper';

@Controller('files')
export class FilesController {
  constructor(private readonly filesService: FilesService) {}

  @Post('product')
  @UseInterceptors(FileInterceptor('file', { fileFilter }))
  uploadFile(@UploadedFile() file: Express.Multer.File) {
    if (!file) {
      throw new BadRequestException('Make sure that the file is an image');
    }
    return { fileName: file.originalname };
  }
}
```

# Resumen mental

UploadedFile toma lo que FileInterceptor aceptó. El filtro decide aceptación y el controlador decide si el archivo es obligatorio y qué respuesta HTTP corresponde. Una etiqueta de tipo y una extensión declarada no sustituyen validar el contenido según el dominio.
