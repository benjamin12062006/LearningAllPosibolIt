## Objetivo de la lección

Paginar y filtrar los items de un usuario dentro de la propia consulta del usuario: quitar el campo de relación del ObjectType y servir `items` con un @ResolveField que recibe @Parent, PaginationArgs y SearchArgs y reutiliza ItemsService.findAll.

## Estado inicial heredado

Clase 125: ItemsService.findAll(user, paginationArgs, searchArgs) con query builder (take, skip, where por userId y búsqueda opcional por nombre). Clase 106 (guía reconstruida): UsersResolver con @ResolveField itemCount y @Parent. User expone `items` como @Field de la relación con Item.

## Fase 1 — Dejar de exponer la relación directa

**Objetivo:** Dejar de exponer la relación directa.

**Código o cambio acumulativo:**

```text
@OneToMany(() => Item, (item) => item.user)
// @Field(() => [Item])
items: Item[];
```


**Por qué:** Con el @Field, GraphQL devolvía todos los items de la relación sin límite. Quitándolo, el campo deja de existir en el esquema, igual que password; la relación de TypeORM se conserva.

**Cómo comprobarlo y resultado esperado:** La consulta users { items { name } } falla porque el campo ya no existe.

**Procedencia:** E4 / E6 / E7.

## Fase 2 — Servir items con un campo resuelto y argumentos propios

**Objetivo:** Servir items con un campo resuelto y argumentos propios.

**Código o cambio acumulativo:**

```text
@ResolveField(() => [Item], { name: 'items' })
async getItemsByUser(
  @CurrentUser([ValidRoles.admin]) adminUser: User,
  @Parent() user: User,
  @Args() paginationArgs: PaginationArgs,
  @Args() searchArgs: SearchArgs,
): Promise<Item[]> {
  return this.itemsService.findAll(user, paginationArgs, searchArgs);
}
```


**Por qué:** El campo se resuelve por cada usuario padre y acepta límite, desplazamiento y búsqueda. Reutiliza findAll, así que la paginación y el filtro son los mismos que en la query items.

**Cómo comprobarlo y resultado esperado:** users { items(limit: 5, search: "rice") { name } } devuelve como mucho 5 items de ese usuario que contienen la palabra.

**Procedencia:** E5 / E8 / E9 / E10 / E11 / E12 / E13 / E14.

## src/items/items.service.ts (findAll, contexto de la clase 125)

Procedencia: E1–E3 (clase 125). Sin cambios en esta clase.

```ts
async findAll(
  user: User,
  paginationArgs: PaginationArgs,
  searchArgs: SearchArgs,
): Promise<Item[]> {
  const { limit, offset } = paginationArgs;
  const { search } = searchArgs;

  const queryBuilder = this.itemsRepository
    .createQueryBuilder()
    .take(limit)
    .skip(offset)
    .where(`"userId" = :userId`, { userId: user.id });

  if (search) {
    queryBuilder.andWhere('LOWER(name) like :name', {
      name: `%${search.toLowerCase()}%`,
    });
  }

  return queryBuilder.getMany();
}
```
