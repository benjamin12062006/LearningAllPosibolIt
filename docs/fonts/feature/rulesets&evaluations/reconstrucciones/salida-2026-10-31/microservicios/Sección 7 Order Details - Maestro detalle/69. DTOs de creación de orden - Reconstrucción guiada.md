## Objetivo de la lección

Sustituir el CreateOrderDto plano (totalAmount, totalItems) por uno que reciba un arreglo items de al menos un elemento, cuyos objetos se validan uno a uno con OrderItemDto mediante @ValidateNested y @Type.

## Estado inicial heredado

Microservicio orders-ms con Prisma y modelos Order y OrderItem; client-gateway reenvía la creación de órdenes. CreateOrderDto contenía totalAmount y totalItems; el código anterior está en la sección 6.

## Fase 1 — Reducir CreateOrderDto a items

**Objetivo:** Reducir CreateOrderDto a items.

**Código o cambio acumulativo:**

```ts
export class CreateOrderDto {
  items: any;
}
```


**Por qué:** El cliente ya no envía totales calculados; envía el detalle y el servidor calcula. any es un marcador temporal hasta crear el DTO hijo.

**Cómo comprobarlo y resultado esperado:** Compila; aún no valida el contenido.

**Procedencia:** E1 / E2.

## Fase 2 — DTO del elemento

**Objetivo:** DTO del elemento.

**Código o cambio acumulativo:**

```ts
import { IsNumber, IsPositive } from 'class-validator';

export class OrderItemDto {
  @IsNumber()
  @IsPositive()
  productId: number;

  @IsNumber()
  @IsPositive()
  quantity: number;

  @IsNumber()
  @IsPositive()
  price: number;
}
```


**Por qué:** Cada elemento tiene su propia forma y reglas; separarlo permite reutilizarlo y que la validación anidada sepa qué instancia construir.

**Cómo comprobarlo y resultado esperado:** El barril exporta OrderItemDto sin errores de importación.

**Procedencia:** E7 / E8 / E9.

## Fase 3 — Validación anidada del arreglo

**Objetivo:** Validación anidada del arreglo.

**Código o cambio acumulativo:**

```ts
import { Type } from 'class-transformer';
import { ArrayMinSize, IsArray, ValidateNested } from 'class-validator';
import { OrderItemDto } from './order-item.dto';

export class CreateOrderDto {
  @IsArray()
  @ArrayMinSize(1)
  @ValidateNested({ each: true })
  @Type(() => OrderItemDto)
  items: OrderItemDto[];
}
```


**Por qué:** @IsArray y @ArrayMinSize validan el contenedor; @ValidateNested({ each: true }) pide validar cada elemento, y @Type transforma cada objeto plano en OrderItemDto para que sus decoradores existan al validar.

**Cómo comprobarlo y resultado esperado:** {} → items debe ser arreglo con al menos un elemento; [{}] → errores items.0.productId…; price "abc" → debe ser número; datos correctos → el DTO llega al microservicio.

**Procedencia:** E3 / E4 / E5 / E6 / E10 / E12.

## Fase 4 — Replicar el contrato en el gateway

**Objetivo:** Replicar el contrato en el gateway.

**Código o cambio acumulativo:**

**Por qué:** El gateway valida antes de enviar el mensaje; ambos lados deben compartir la misma forma.

**Procedencia:** E11.

# Resumen mental

JSON → ValidationPipe → @Type crea una instancia de OrderItemDto por elemento → @ValidateNested({ each: true }) ejecuta sus decoradores → errores con ruta items.N.propiedad. Sin @Type el elemento sigue siendo un objeto plano y sus reglas no se aplican.
