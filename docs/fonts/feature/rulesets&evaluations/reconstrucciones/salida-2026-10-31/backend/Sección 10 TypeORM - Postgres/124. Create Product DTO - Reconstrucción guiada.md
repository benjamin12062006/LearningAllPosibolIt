## Objetivo de la lección

Definir CreateProductDto con class-validator para que POST /api/products rechace con 400 los cuerpos que no cumplen el contrato: título obligatorio, campos opcionales tipados, arreglo de tallas con elementos string y género restringido a una lista cerrada.

## Estado inicial heredado

Proyecto TesloShop con el recurso products generado por Nest CLI (controller, service, DTOs vacíos) y la entidad Product de las clases 122–123. Postman devuelve 404 en /api/products porque todavía no existe el prefijo global.

## Fase 1 — Prefijo global y ValidationPipe

**Objetivo:** Prefijo global y ValidationPipe.

**Código o cambio acumulativo:**

```ts
import { ValidationPipe } from '@nestjs/common';
import { NestFactory } from '@nestjs/core';
import { AppModule } from './app.module';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);

  app.setGlobalPrefix('api');

  app.useGlobalPipes(
    new ValidationPipe({
      whitelist: true,
      forbidNonWhitelisted: true,
    }),
  );

  await app.listen(3000);
}
bootstrap();
```


**Por qué:** Sin prefijo la ruta /api/products no existe (404) y sin el pipe global los decoradores del DTO no se ejecutan: habría que validar a mano en el controlador.

**Cómo comprobarlo y resultado esperado:** POST /api/products con body {} responde la acción del servicio en lugar de 404.

**Procedencia:** E1 / E2 / E11.

## Fase 3 — Decoradores de los campos escalares

**Objetivo:** Decoradores de los campos escalares.

**Código o cambio acumulativo:**

```ts
@IsString()
@MinLength(1)
title: string;

@IsNumber()
@IsPositive()
@IsOptional()
price?: number;

@IsInt()
@IsPositive()
@IsOptional()
stock?: number;
```


**Por qué:** El signo ? solo afecta a TypeScript; @IsOptional es lo que permite omitir el campo en tiempo de ejecución. stock usa @IsInt porque no admite decimales, a diferencia de price.

**Cómo comprobarlo y resultado esperado:** Enviar title vacío o price negativo produce errores de validación.

**Procedencia:** E5 / E6 / E7.

## Fase 4 — Arreglos y valores cerrados

**Objetivo:** Arreglos y valores cerrados.

**Código o cambio acumulativo:**

```ts
@IsString({ each: true })
@IsArray()
sizes: string[];

@IsIn(['men', 'women', 'kid', 'unisex'])
gender: string;
```


**Por qué:** each: true aplica la regla a cada elemento del arreglo y @IsIn limita un string a un conjunto conocido, sin crear un enum.

**Cómo comprobarlo y resultado esperado:** Body vacío: mensajes de title, sizes (arreglo y cada valor string) y gender; Bad Request.

**Procedencia:** E8 / E9 / E10.

## src/products/dto/create-product.dto.ts

Procedencia: E3–E4 propiedades; E5 title; E6 price/description/slug; E7 stock; E8 sizes y gender; E10 valores normalizados.

```ts
import {
  IsArray,
  IsIn,
  IsInt,
  IsNumber,
  IsOptional,
  IsPositive,
  IsString,
  MinLength,
} from 'class-validator';

export class CreateProductDto {
  @IsString()
  @MinLength(1)
  title: string;

  @IsNumber()
  @IsPositive()
  @IsOptional()
  price?: number;

  @IsString()
  @IsOptional()
  description?: string;

  @IsString()
  @IsOptional()
  slug?: string;

  @IsInt()
  @IsPositive()
  @IsOptional()
  stock?: number;

  @IsString({ each: true })
  @IsArray()
  sizes: string[];

  @IsIn(['men', 'women', 'kid', 'unisex'])
  gender: string;
}
```
