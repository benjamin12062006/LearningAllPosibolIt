## Objetivo de la lección

Sustituir la guarda basada en la existencia de una propiedad ('path' in source) por una unión discriminada: cada miembro de Source tiene una propiedad type con un literal distinto y loadData decide la rama comparando ese valor, con narrowing completo de TypeScript.

## Estado inicial heredado

Archivo adjunto guards.ts de la clase 90: tipos FileSource { path } y DBSource { connectionUrl }, unión Source y función loadData(source: Source) que comprueba if ('path' in source) y retorna, de modo que después TypeScript sabe que source es DBSource.

## Fase 1 — Estado heredado: guarda por propiedad

**Objetivo:** Estado heredado: guarda por propiedad.

**Código o cambio acumulativo:**

```ts
type FileSource = { path: string };
type DBSource = { connectionUrl: string };
type Source = FileSource | DBSource;

function loadData(source: Source) {
  if ('path' in source) {
    source.path;
    return;
  }
  source.connectionUrl;
}
```


**Por qué:** Funciona, pero acopla la decisión al nombre de una propiedad que podría cambiar.

**Cómo comprobarlo y resultado esperado:** TypeScript permite source.connectionUrl después del if.

**Procedencia:** E1 / E2 / E3 / E4.

## Fase 2 — Añadir el discriminante literal

**Objetivo:** Añadir el discriminante literal.

**Código o cambio acumulativo:**

```ts
type FileSource = { type: 'file'; path: string };
type DBSource = { type: 'db'; connectionUrl: string };
```


**Por qué:** type no es cualquier string sino un literal; la unión de ambos tipos infiere source.type como 'file' | 'db'.

**Cómo comprobarlo y resultado esperado:** Un objeto FileSource sin type: 'file' da error de compilación.

**Procedencia:** E5 / E6 / E7.

## Fase 3 — Decidir por el discriminante

**Objetivo:** Decidir por el discriminante.

**Código o cambio acumulativo:**

```ts
function loadData(source: Source) {
  if (source.type === 'file') {
    source.path;
    return;
  }
  source.connectionUrl;
}
```


**Por qué:** type existe en todos los miembros, así que se puede leer sin guarda; su valor estrecha el tipo en cada rama.

**Cómo comprobarlo y resultado esperado:** Dentro del if solo autocompleta path; fuera, connectionUrl.

**Procedencia:** E8 / E9 / E10.

## guards.ts

Procedencia: E2/E6 tipos; E7 objetos (valores de ejemplo ensamblados); E8–E9 loadData.

```ts
type FileSource = { type: 'file'; path: string };
const fileSource: FileSource = {
  type: 'file',
  path: 'some/path/to/file.csv',
};

type DBSource = { type: 'db'; connectionUrl: string };
const dbSource: DBSource = {
  type: 'db',
  connectionUrl: 'some-connection-url',
};

type Source = FileSource | DBSource;

function loadData(source: Source) {
  if (source.type === 'file') {
    source.path; // => use that to open the file
    return;
  }
  source.connectionUrl; // => to reach out to database
}
```

# Resumen mental

Unión de tipos con una propiedad común de valor literal distinto → comprobar ese valor → TypeScript estrecha al miembro correspondiente en cada rama. Es más estable que comprobar la existencia de propiedades específicas.
