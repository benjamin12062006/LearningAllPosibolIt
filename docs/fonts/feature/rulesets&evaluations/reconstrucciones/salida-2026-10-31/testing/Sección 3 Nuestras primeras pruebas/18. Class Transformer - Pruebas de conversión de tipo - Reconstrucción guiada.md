## Objetivo de la lección

Probar que PaginationDto convierte strings de query en números. validate() de class-validator no ejecuta @Type, así que la prueba debe construir el DTO con plainToInstance de class-transformer y comprobar tanto la ausencia de errores como el tipo resultante.

## Estado inicial heredado

Proyecto MyPokemonApp con src/shared/dtos/pagination.dto.ts (page y limit opcionales, numéricos, transformados con @Type y mínimo 1) y su spec con pruebas de valores por defecto e inválidos que usan new PaginationDto() y validate().

## Fase 1 — Intento con una instancia creada con new

**Objetivo:** Intento con una instancia creada con new.

**Código o cambio acumulativo:**

```ts
it('should convert strings into numbers', async () => {
  const dto = new PaginationDto();
  dto.page = '10' as unknown as number;
  dto.limit = '10' as unknown as number;

  const errors = await validate(dto);
  console.log(errors.length);
  expect(errors.length).toBe(0);
});
```


**Por qué:** Se simula la query con strings. La prueba falla: validate solo ejecuta decoradores de class-validator; @Type nunca se aplicó y page sigue siendo string.

**Cómo comprobarlo y resultado esperado:** Jest muestra errores de page/limit: deben ser números.

**Procedencia:** E5 / E6 / E7 / E8.

## Fase 2 — Construir el DTO como lo hace Nest

**Objetivo:** Construir el DTO como lo hace Nest.

**Código o cambio acumulativo:**

```ts
const input = { limit: '10', page: '2' };
const dto = plainToInstance(PaginationDto, input);

const errors = await validate(dto);
expect(errors.length).toBe(0);
```


**Por qué:** plainToInstance hace la parte de class-transformer (objeto plano → instancia con @Type aplicado); después validate comprueba las reglas.

**Cómo comprobarlo y resultado esperado:** La prueba pasa y el log de errores es un arreglo vacío.

**Procedencia:** E9.

## Fase 3 — Comprobar lo que dice el título de la prueba

**Objetivo:** Comprobar lo que dice el título de la prueba.

**Código o cambio acumulativo:**

```ts
expect(dto.limit).toBe(10);
expect(dto.page).toBe(2);
```


**Por qué:** Cero errores no demuestra la conversión. toBe compara valor y tipo como ===, así que '2' no pasa por 2.

**Cómo comprobarlo y resultado esperado:** Quitar @Type(() => Number) de PaginationDto hace fallar la prueba.

**Procedencia:** E10 / E11.

## src/shared/dtos/pagination.dto.ts

Procedencia: E1–E3 (clase 13). Orden de decoradores ensamblado.

```ts
import { Type } from 'class-transformer';
import { IsNumber, IsOptional, Min } from 'class-validator';

export class PaginationDto {
  @IsOptional()
  @IsNumber()
  @Type(() => Number)
  @Min(1)
  page?: number;

  @IsOptional()
  @IsNumber()
  @Type(() => Number)
  @Min(1)
  limit?: number;
}
```

## src/shared/dtos/pagination.dto.spec.ts

Procedencia: E4 reflect-metadata; E5 título; E9 plainToInstance; E10 aserciones. Las pruebas de 16–17 se omiten y se indican en un comentario.

```ts
import 'reflect-metadata';
import { plainToInstance } from 'class-transformer';
import { validate } from 'class-validator';
import { PaginationDto } from './pagination.dto';

describe('PaginationDto', () => {
  // Las pruebas de valores por defecto y valores inválidos de las clases 16–17 siguen aquí.

  it('should convert strings into numbers', async () => {
    const input = { limit: '10', page: '2' };
    const dto = plainToInstance(PaginationDto, input);

    const errors = await validate(dto);

    expect(errors.length).toBe(0);
    expect(dto.limit).toBe(10);
    expect(dto.page).toBe(2);
  });
});
```

# Resumen mental

Nest hace plainToInstance (transformar) y luego validate (validar). Una prueba unitaria de un DTO con @Type debe repetir esas dos fases; validate sola no transforma. Comprobar el valor convertido con toBe, que distingue '2' de 2.
