## Objetivo de la lección

Escribir las pruebas unitarias de CreatePokemonDto con validate() de class-validator: un caso válido con los datos mínimos y un caso inválido por cada propiedad obligatoria, buscando el error por su property para que la prueba no dependa del orden ni del número de errores.

## Estado inicial heredado

CreatePokemonDto con name y type obligatorios (@IsNotEmpty, @IsString), hp opcional numérico con mínimo 0 y sprites opcional como arreglo de strings. Jest configurado y reflect-metadata instalado como dependencia de desarrollo.

## Fase 1 — Caso válido con datos mínimos

**Objetivo:** Caso válido con datos mínimos.

**Código o cambio acumulativo:**

```ts
import 'reflect-metadata';
import { validate } from 'class-validator';
import { CreatePokemonDto } from './create-pokemon.dto';

describe('CreatePokemonDto', () => {
  it('should be valid with correct data', async () => {
    const dto = new CreatePokemonDto();
    dto.name = 'Pikachu';
    dto.type = 'Electric';

    const errors = await validate(dto);

    expect(errors.length).toBe(0);
  });
});
```


**Por qué:** Fija el contrato mínimo: si mañana se añade un campo obligatorio, esta prueba avisa.

**Cómo comprobarlo y resultado esperado:** La prueba pasa.

**Procedencia:** E4 / E5 / E6 / E7.

## Fase 2 — Prueba frágil del error de name

**Objetivo:** Prueba frágil del error de name.

**Código o cambio acumulativo:**

```ts
it('should be invalid if name is not present', async () => {
  const dto = new CreatePokemonDto();
  dto.type = 'Electric';

  const errors = await validate(dto);
  const [nameError] = errors;

  expect(nameError.property).toBe('name');
});
```


**Por qué:** Funciona hoy, pero depende de que el error de name sea el primero.

**Cómo comprobarlo y resultado esperado:** Añadir anotherRequiredProperty obligatoria al inicio del DTO rompe esta prueba sin que haya cambiado name.

**Procedencia:** E8 / E9 / E10.

## Fase 3 — Buscar el error por propiedad

**Objetivo:** Buscar el error por propiedad.

**Código o cambio acumulativo:**

```ts
const errors = await validate(dto);
const nameError = errors.find((error) => error.property === 'name');

expect(nameError).toBeDefined();
```


**Por qué:** find devuelve el ValidationError de name o undefined; la prueba solo se interesa por esa propiedad y tolera otros errores.

**Cómo comprobarlo y resultado esperado:** Con la propiedad extra la prueba sigue pasando; si se busca 'name2' falla con undefined.

**Procedencia:** E11 / E12.

## src/pokemons/dto/create-pokemon.dto.ts

Procedencia: E1–E3 (clase 13). Ruta asumida por convención del recurso.

```ts
import {
  IsArray,
  IsNotEmpty,
  IsNumber,
  IsOptional,
  IsString,
  Min,
} from 'class-validator';

export class CreatePokemonDto {
  @IsNotEmpty()
  @IsString()
  name: string;

  @IsNotEmpty()
  @IsString()
  type: string;

  @IsOptional()
  @IsNumber()
  @Min(0)
  hp?: number;

  @IsOptional()
  @IsArray()
  @IsString({ each: true })
  sprites?: string[];
}
```
