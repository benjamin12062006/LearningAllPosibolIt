## Objetivo de la lección

Servir de forma controlada una imagen subida: un GET recibe solo el nombre del archivo, el servicio construye la ruta dentro de una carpeta fija del servidor, comprueba que exista sin revelar la ruta en el error y el controlador envía el archivo con @Res() y res.sendFile().

## Fase 3 — Servicio que construye la ruta y comprueba existencia

**Objetivo:** Servicio que construye la ruta y comprueba existencia.

**Código o cambio acumulativo:**

```text
import { BadRequestException, Injectable } from '@nestjs/common';
import { existsSync } from 'fs';
import { join } from 'path';

@Injectable()
export class FilesService {
  getStaticProductImage(imageName: string) {
    const path = join(__dirname, '../static/products', imageName);

    if (!existsSync(path))
      throw new BadRequestException(`No product found with image ${imageName}`);

    return path;
  }
}
```


**Por qué:** La lógica de archivos va al servicio. join compone la ruta dentro de una carpeta fija; si no existe, el error no revela la ruta física.

**Cómo comprobarlo y resultado esperado:** Pedir un nombre inexistente responde 400 con el mensaje y sin ruta.

**Procedencia:** E5 / E6 / E7 / E8 / E9 / E10 / E11.

## Fase 4 — Responder manualmente con @Res y sendFile

**Objetivo:** Responder manualmente con @Res y sendFile.

**Código o cambio acumulativo:**

```text
@Get('product/:imageName')
findProductImage(
  @Res() res: Response,
  @Param('imageName') imageName: string,
) {
  const path = this.filesService.getStaticProductImage(imageName);

  res.sendFile(path);
}
```


**Por qué:** Con @Res el método toma el control de la respuesta y Nest deja de enviar el return. Se pierde parte del ciclo de vida (interceptores globales), a cambio de enviar el archivo.

**Cómo comprobarlo y resultado esperado:** GET con un nombre existente muestra la imagen en Postman o en el navegador.

**Procedencia:** E13 / E14 / E16 / E17 / E18.

import { BadRequestException, Injectable } from '@nestjs/common';
import { existsSync } from 'fs';
import { join } from 'path';

@Injectable()
export class FilesService {
  getStaticProductImage(imageName: string) {
    const path = join(__dirname, '../static/products', imageName);

    if (!existsSync(path))
      throw new BadRequestException(`No product found with image ${imageName}`);

    return path;
  }
}

## src/files/files.controller.ts

Procedencia: E1–E4, E13–E17; POST, interceptor y helpers heredados de la clase 157 (guía reconstruida).

```ts
import {
  BadRequestException,
  Controller,
  Get,
  Param,
  Post,
  Res,
  UploadedFile,
  UseInterceptors,
} from '@nestjs/common';
import { FileInterceptor } from '@nestjs/platform-express';
import { Response } from 'express';
import { diskStorage } from 'multer';
import { FilesService } from './files.service';
import { fileFilter, fileNamer } from './helpers';

@Controller('files')
export class FilesController {
  constructor(private readonly filesService: FilesService) {}

  @Get('product/:imageName')
  findProductImage(
    @Res() res: Response,
    @Param('imageName') imageName: string,
  ) {
    const path = this.filesService.getStaticProductImage(imageName);

    res.sendFile(path);
  }

  @Post('product')
  @UseInterceptors(FileInterceptor('file', {
    fileFilter,
    storage: diskStorage({
      destination: './static/products',
      filename: fileNamer,
    }),
  }))
  uploadFile(@UploadedFile() file: Express.Multer.File) {
    if (!file) {
      throw new BadRequestException('Make sure that the file is an image');
    }

    const secureUrl = `${file.filename}`;

    return { secureUrl };
  }
}
```

# Resumen mental

El cliente solo nombra el recurso; el servidor decide la carpeta, comprueba que exista y responde sin revelar dónde está. @Res da control total de la respuesta a cambio de salirse de parte del ciclo de vida de Nest.
