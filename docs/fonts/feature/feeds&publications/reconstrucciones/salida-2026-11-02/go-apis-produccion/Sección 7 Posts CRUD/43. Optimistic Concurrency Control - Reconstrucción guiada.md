## Objetivo de la lección

Evitar que dos actualizaciones simultáneas del mismo post se pisen: añadir una columna `version`, leerla junto al post, actualizar solo si sigue siendo la leída (`WHERE version = $n`), incrementarla en la misma sentencia y devolver la nueva con `RETURNING`. Si no se actualiza ninguna fila, la operación falla.

## Estado inicial heredado

API de posts en Go con PostgreSQL. El handler PATCH lee el post (GetByID en un middleware de contexto), cambia los campos recibidos y llama a `Update` del store, que hace un UPDATE sin condición de versión. Un script lanza dos peticiones a la vez: una cambia el título y otra el contenido.

## Fase 1 — Reproducir la actualización perdida

**Objetivo:** Reproducir la actualización perdida.

**Código o cambio acumulativo:**

```text
// Dos peticiones PATCH simultáneas sobre el mismo post:
// A envía { "title": "new title" } y B envía { "content": "new content" }.
// Las dos leen el post antes de escribir, así que la última pisa el cambio de la otra.
```


**Por qué:** El handler lee, modifica en memoria y escribe la fila entera; entre leer y escribir otra petición puede haber cambiado el registro.

**Cómo comprobarlo y resultado esperado:** Tras varias ejecuciones, a veces solo queda el título nuevo y a veces solo el contenido nuevo.

**Procedencia:** E1 / E2.

**Por qué:** La versión identifica qué estado del registro leyó cada petición.

**Cómo comprobarlo y resultado esperado:** Tras migrar, todos los posts tienen version = 0.

## Fase 4 — Actualizar solo si la versión no cambió

**Objetivo:** Actualizar solo si la versión no cambió.

**Código o cambio acumulativo:**

```text
func (s *PostStore) Update(ctx context.Context, post *Post) error {
	query := `
		UPDATE posts
		SET title = $1, content = $2, version = version + 1
		WHERE id = $3 AND version = $4
		RETURNING version
	`

	err := s.db.QueryRowContext(ctx, query, post.Title, post.Content, post.ID, post.Version).Scan(&post.Version)
	if err != nil {
		switch {
		case errors.Is(err, sql.ErrNoRows):
			return ErrNotFound
		default:
			return err
		}
	}

	return nil
}
```


**Por qué:** La comprobación y el incremento ocurren en una sola sentencia: si otra petición ya subió la versión, la condición no encuentra la fila y no se escribe nada. RETURNING devuelve la versión nueva sin otra consulta.

**Cómo comprobarlo y resultado esperado:** Con dos peticiones simultáneas, una responde 200 y la otra falla; el registro conserva un cambio completo, nunca una mezcla.

**Procedencia:** E4 / E5 / E8 / E10 / E11 / E12 / E13.

# Resumen mental

Concurrencia optimista: cada escritura dice qué versión leyó; la base de datos solo acepta la escritura si esa versión sigue vigente y la incrementa en la misma sentencia. Si no coincide, nadie se bloquea: la petición tardía falla y debe volver a leer.
