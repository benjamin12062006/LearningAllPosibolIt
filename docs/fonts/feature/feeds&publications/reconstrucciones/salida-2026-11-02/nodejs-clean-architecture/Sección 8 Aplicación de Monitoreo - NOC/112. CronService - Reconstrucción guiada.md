## Objetivo de la lección

Aislar el paquete `cron` detrás de una clase propia, `CronService`, con un método `createJob(cronTime, onTick)` que crea, arranca y devuelve el trabajo, para que el resto de la aplicación no dependa del paquete.

## Estado inicial heredado

Clase 111: `npm i cron`; en `Server.start` se crea directamente `new CronJob('*/2 * * * * *', …)` y se llama a `job.start()`. El instructor advierte que ese código está acoplado al paquete.

## Fase 1 — Mover el trabajo a un servicio propio

**Objetivo:** Mover el trabajo a un servicio propio.

**Código o cambio acumulativo:**

```text
import { CronJob } from 'cron';

export class CronService {
  static createJob() {
    const job = new CronJob('*/5 * * * * *', () => {
      const date = new Date();
      console.log('5 seconds', date);
    });

    job.start();
    return job;
  }
}
```


**Por qué:** El servidor deja de importar el paquete; solo este archivo lo conoce.

**Cómo comprobarlo y resultado esperado:** La aplicación sigue imprimiendo cada cinco segundos.

**Procedencia:** E1 / E3 / E4 / E5 / E6 / E7 / E13.

## Fase 2 — Recibir el horario y la tarea con tipos propios

**Objetivo:** Recibir el horario y la tarea con tipos propios.

**Código o cambio acumulativo:**

```text
import { CronJob } from 'cron';

type CronTime = string | Date;
type OnTick = () => void;

export class CronService {
  static createJob(cronTime: CronTime, onTick: OnTick): CronJob {
    const job = new CronJob(cronTime, onTick);

    job.start();
    return job;
  }
}
```


**Por qué:** Los tipos propios describen solo lo que la aplicación usa (texto cron o fecha, y una función sin argumentos), no toda la firma del paquete.

**Cómo comprobarlo y resultado esperado:** TypeScript no marca any en los argumentos.

**Procedencia:** E8 / E9 / E10 / E11.

## Fase 3 — Usarlo desde el servidor

**Objetivo:** Usarlo desde el servidor.

**Código o cambio acumulativo:**

```text
export class Server {
  public static start() {
    console.log('Server started...');

    CronService.createJob('*/5 * * * * *', () => {
      const date = new Date();
      console.log('5 seconds', date);
    });
  }
}
```


**Por qué:** El servidor declara qué hacer y cuándo; el detalle de la librería queda fuera.

**Cómo comprobarlo y resultado esperado:** Con varios trabajos (cada 2, 3 y 5 segundos) cada uno se dispara a su ritmo.

**Procedencia:** E2 / E12 / E14.

# Resumen mental

Un paquete de programación se envuelve en un adaptador pequeño: la aplicación pide «ejecuta esto con este horario» y recibe algo que puede detener. Cambiar de librería solo toca el adaptador.
